# Project Rules

## 1. 커밋 메시지 스타일 (Commit Message Style)
- 작업 완료 후 커밋 메시지를 작성할 때 기존의 규칙을 항상 따른다.
- **머릿말 (Conventional Commits)**: `feat(ui):`, `fix(api):`, `style(history):` 등 변경 성격과 도메인을 명시한다.
- **문체**: `~한다`, `~이다` 형태의 간결한 평어체(현재형)로 작성한다.
- **내용 (Body)**: 단순히 '무엇을 바꿨다'가 아니라, '어떤 문제가 있었고(또는 왜 바꿨고) 어떻게 동작하게 했는지'를 구체적인 맥락과 스토리로 작성한다.

## 2. 임시 파일 관리 (Temporary Files)
- 테스트를 위해 생성한 임시 스크립트, 데이터 파일, 또는 백그라운드 패키지(`node_modules`, `package.json` 등)는 **테스트가 끝난 직후 항상 즉시 삭제**하여 워크스페이스(git 상태)를 깔끔하게 유지한다.
